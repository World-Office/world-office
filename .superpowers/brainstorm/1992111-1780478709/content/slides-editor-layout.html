Three Approaches for Data Storage

Before we dive into the UI, let's decide the technical foundation:

A

Recommended — JSON-Native + PPTX Export

Store presentations as JSON. Generate PPTX only on export via a simple OOXML builder. No PPTX import.

Pros

  • Fastest to implement
  • Simple data model
  • No complex OOXML parsing

Cons

  • Can't open existing PPTX files
  • Need to build export path from scratch
B

OOXML-Native — Full PPTX Roundtrip

Build wo-pptx format crate (following wo-docx pattern). Store/load as PPTX internally.

Pros

  • Full format compatibility
  • Can open any existing PPTX
  • Follows established patterns

Cons

  • 2-3x more backend work
  • Complex OOXML schema
  • Heavy for MVP
C

Hybrid — JSON Editing + PPTX Export + Simple Import

JSON for fast editing. Build a minimal PPTX export & a basic outline importer (text extraction from OOXML).

Pros

  • Fast editing experience
  • Can import basic PPTX content
  • Real PPTX output

Cons

  • Two formats to maintain
  • Import will be lossy for complex decks
