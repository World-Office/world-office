Frontend — Editor Layout & Components

MVP component structure for presentationeditor-react

Component Tree

App
├── Toolbar — File | Home | Insert | Design
│   ├── File: New, Open, Save As PPTX
│   ├── Home: Text Format (B/I/U/S, font, size)
│   └── Insert: Text Box, Picture
├── Main Area
│   ├── Left: SlideThumbnails (list, drag reorder)
│   ├── Center: SlideCanvas (WYSIWYG, drag/resize shapes)
│   └── Right: PropertiesPanel (selected shape properties)
└── StatusBar — slide N of M, zoom level

Data Flow

Load: PPTX → wo-ooxml parser → PptxPresentation → MobX PresentationStore → Canvas Renderer
Save: PresentationStore → PptxPresentation → wo-ooxml serializer → PPTX file download
Edit: User drags shape → Canvas events → PresentationStore.updateShape() → Re-render

Question: Canvas Rendering Strategy

A

HTML/CSS Canvas

Absolutely positioned divs. CSS transforms for drag/resize. Easier to implement, looks native.

B

SVG Canvas

SVG elements for shapes. Good for drawing. More work for text editing.

C

WASM Canvas (wo-renderer-wasm)

Uses existing wo-renderer-wasm. Most performant. Most complex integration.
