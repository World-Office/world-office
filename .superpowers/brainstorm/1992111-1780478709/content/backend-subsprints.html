Backend Implementation — Sub-Sprint Breakdown

wo-ooxml PPTX extension split into 3 independent sub-sprints

Sub-Sprint 1: Slide Manager (Frontend-Only)

No PPTX backend needed yet. JSON-native for storage.

  • SlideThumbnails — list/select/add/delete/duplicate slides
  • SlideCanvas — render slide background, slide navigation
  • Slide navigation — previous/next, jump to slide
  • Storage — save/load as JSON (temp, replaced in SS2)

Sub-Sprint 2: PPTX Backend (wo-ooxml Extension)

Pure Rust, independently testable with cargo test.

  • Phase 1: PptxPresentation model + minimal PPTX serializer (create PPTX from scratch)
  • Phase 2: PPTX parser (read existing PPTX files)
  • Phase 3: Roundtrip tests + FormatRoundtrip integration

Sub-Sprint 3: Content Editing (Frontend + Backend Integration)

Wire frontend to real PPTX backend.

  • Shape CRUD — add/move/resize text boxes, images on canvas
  • Text editing — inline formatting via toolbar
  • Image insertion — upload + embed in PPTX
  • Properties panel — selected shape position/size/text props

Proposed Order

SS1 → SS2 → SS3
Frontend scaffolding first, then backend, then integration.
Each sub-sprint independently testable.
